# Operator Registry — who’s running this in the wild

Forks are independent. We have no telemetry, no reporting rights, and no back door —
that is deliberate, and it is why operators trust the code enough to fork it.
This registry is the opposite of surveillance: **operators list themselves, voluntarily,
because being listed is useful.**

## Why list yourself

- Families crossing borders can find operators running compatible systems.
- Operators find each other — shared vendor patterns, shared bug fixes, shared lessons.
- It signals to the next fork that the pattern works somewhere real.

## How to list (via pull request)

Add a row to the table below. All fields except name and country are optional —
share only what you’re comfortable making public.

| Operator / Project | Country | Website / Contact | Scale (residents, approx.) | Status | Notes |
|---|---|---|---|---|---|
| *(example)* Harbor Light | Turkey | hello@example.com | ~40 | Active | Istanbul home-mode deployment |

**Status** is one of: `Active`, `Pilot`, `Paused`, `Retired`.
Update your row when things change; remove it if you shut down. Stale rows get
pruned once a year.

## What listing means

- Nothing obligatory. No reporting duties, no fees, no permission needed to delist.
- It does **not** grant trademark rights — see FORKING.md’s brand rule. Listed operators
  may describe themselves as “running a Chumreap OS–derived system”; the name
  “Chumreap” itself still requires written permission for commercial use.
- We may contact listed operators occasionally (a yearly check-in, a security notice
  for the core). Opt out anytime by delisting.

## What we’ll never ask for

Resident data. Event contents. Anything personal. The registry tracks *operators*,
never the people they serve — that would contradict everything the architecture stands for.
